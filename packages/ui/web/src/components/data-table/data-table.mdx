# Data table

Rows of data under a header row, which compare a few attributes across rows, such as the data that the Privacy page lists. It is the Data table component of the design system in Penpot.

<Canvas of={DataTableStories.Desktop} />

## Placing a data table

Data table is an attribute on `<table>`. Give it a `<caption>`, a `<thead>` with one row of `<th scope="col">`, and a `<tbody>` whose rows start with a `<th scope="row">`:

```html
<table dma-data-table>
    <caption>Data we process</caption>
    <thead>
        <tr>
            <th scope="col">Data</th>
            <th scope="col">Kept for</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">Server logs</th>
            <td>14 days</td>
        </tr>
    </tbody>
</table>
```

Write the `<thead>` and `<tbody>` yourself, since Angular adds neither. The table is as wide as its container, up to the measure of 720 px (`--size-measure`), so in a wider container, such as the canvas above, it stops at 720 px. It leaves its own place in the container to the section that holds it.

The browser sizes each column from its content, so the longest column takes the most room, as in Penpot. To fix the width of a column, set it on a `<col>` in a `<colgroup>` after the caption.

## Viewport

The layout follows the desktop breakpoint of `@critsource/design-tokens`, so the data table takes no input for it.

### Desktop

From the breakpoint up, the rows sit under the header row, as the data table at the top of this page shows. The header row sits on the sunken background, and a divider splits each row from the one above it. The first cell of each row names it in strong body text; the other cells hold its data in small, muted body text.

### Mobile

Below the breakpoint, each row is a card, since the columns would leave each cell too little room. The first cell titles the card, and each other cell draws the label of its column above its data. The component copies each label from the text of the column header, again whenever the rows or the header row change, so a page sets no labels of its own.

## Focus

A data table takes no focus, and Penpot draws no hover or focus state for it, since it is not interactive. A Link in a cell draws its own focus ring.

## Accessibility

The caption names the table for assistive technology and stays out of sight, since the heading of the section names it on the page. The `scope` of each `<th>` tells assistive technology which cells it heads, so a screen reader reads each cell with its column and its row.

Below the breakpoint, the header row leaves the screen but stays in the accessibility tree, so a screen reader still announces a table and reads each cell with its column. The card layout drops the table semantics of the elements in some browsers, so the component sets their roles itself. The label on each cell takes no text alternative, since a screen reader already reads the column header with the cell.

## Testing

`DataTableHarness` from `@critsource/ui-web/testing` reads a data table in a test: its caption and its size, the text, look, padding, box, and column label of each cell, the box, card border, and divider of each row, its border, and its width.
