# Summary

The box that opens a long text page with a short version of it, such as In short on the Privacy page and At a glance on the Accessibility page. It is the Summary component of the design system in Penpot.

<Canvas of={SummaryStories.Points} />

## Placing a summary

Summary is an attribute on `<section>`. Project a heading with `dma-summary-title` as its title, then a `<ul role="list">` of its points:

```html
<section dma-summary>
    <h2 dma-summary-title>In short</h2>
    <ul role="list">
        <li>No accounts, no cookies, no analytics, and no ads.</li>
        <li>Your theme choice stays in your browser and never reaches us.</li>
    </ul>
</section>
```

Each point draws a muted marker 12 px before its text, and a line that wraps starts under the text. The points sit 8 px apart.

Make the title an `<h2>` under the title of the page, so the summary shows in the headings list of a screen reader. The title draws the same at every level.

Place the summary under the title block of the page. It fills its container up to the measure, 720 px, and leaves its own place in the container to the page that holds it. Penpot draws it the same in both viewports, so it takes no input for them.

## Focus

A summary takes no focus, and Penpot draws no hover or focus state for it, since it is not interactive. A Link in a point draws its own focus ring.

## Accessibility

The title names the section, so assistive technology announces the summary as a region by that name. The points drop the markers of their list, which makes Safari drop its list role, so give the `<ul>` `role="list"`. Screen readers skip the markers the summary draws. The title binds an id, generated unless you set one, and the section points `aria-labelledby` at it. A summary without a title throws NG0951.

## Testing

`SummaryHarness` from `@dnd-mapp/ui-web/testing` reads a summary in a test: its title and points, the id that names it, the look of its box and title, and the place of its parts.
